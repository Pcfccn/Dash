# Свой одометр по GPS и расход топлива

**Статус:** проект, не реализовано. 2026-10-11. Опирается на GPS из [gps-performance-meter.md](gps-performance-meter.md); железо для чистовой сборки — в [build-hardware.md](build-hardware.md).

## 1. Что показываем

### Пробег

| Счётчик | Что это | Когда обнуляется |
|---|---|---|
| **ОБЩИЙ** | весь пробег с установки | никогда (только служебной процедурой на DIAG) |
| **ПОЕЗДКА** | текущая поездка | сам, при включении после стоянки дольше 30 мин (время берётся из GPS) |
| **СЧЁТЧИК A** | с последнего ручного сброса | вручную |
| С заправки (опционально) | с последней заправки | сам, когда уровень в баке скачком вырос на стоянке (если ECM отдаёт уровень, PID `0x2F`) |

### Расход

| Показатель | Как считается |
|---|---|
| **Мгновенный** | л/100 км при движении от 5 км/ч; на месте — л/ч (л/100 км там бессмысленны) |
| **За поездку** | литры и средний л/100 км для ПОЕЗДКИ и СЧЁТЧИКА A |
| **Средний** | для СЧЁТЧИКА A (с последнего сброса) и для ОБЩЕГО (за всё время) |
| Запас хода (бонус) | топливо в баке × 100 / средний расход. Нужны уровень `0x2F` и объём бака (у RG 76 л, проверить) |

Это свой одометр, а не замена штатного. Штатный обычно завышает на 1–3 %, и расхождение с GPS — нормально.

## 2. Пробег: откуда брать расстояние

**Интегрировать доплеровскую скорость GNSS, а не складывать расстояния между координатами.** Координаты на стоянке «гуляют» на метры, и сумма отрезков набегает даже у стоящей машины. Скорость `gSpeed` из UBX-NAV-PVT точнее (у u-blox порядка 0.05 м/с, модуль сам отдаёт оценку `sAcc`), а интеграл по времени эпох (`iTOW`) не зависит от тормозов суперцикла:

```
d += gSpeed × Δt(iTOW)        если fixType = 3D, sAcc ≤ 0.5 м/с, numSV ≥ 6
gSpeed < 0.3 м/с  →  0        дрейф на стоянке (у u-blox есть ещё static hold)
```

**Там, где нет GPS** — тоннели, паркинги, первые ~30 с после холодного старта — берём скорость машины × поправку `K`:
- Источник: широковещательный кадр **`0x3E9` ECMVehicleSpeed**, шаг 0.01 mph, по [opendbc](https://github.com/commaai/opendbc). Его не нужно запрашивать, и он точнее PID `0x0D` (шаг 1 км/ч). На RG он, скорее всего, есть: `0x0C9` и `0x1F5` уже совпали с тем же файлом opendbc. Проверить на SNIFF. Если кадра нет — PID `0x0D`, как сейчас.
- `K` обучается по GPS: при ровном движении от 30 км/ч и хорошем фиксе `K` = скользящее среднее отношения GPS / скорость машины. Хранится вместе с пробегом. Заодно заменяет зашитый `SPEED_GPS_SCALE` (60/67 по одной точке), и плитка скорости без GPS тоже станет точной.
- Время для скорости машины — время приёма кадра в прерывании, как уже сделано для всех метрик.

Ожидаемая точность GPS-одометра — доли процента. Сначала проверить: 10 км по ровной трассе против штатного одометра и отметок.

## 3. Расход топлива: откуда брать

**Главное: у дизеля нельзя считать расход по воздуху (MAF), как у бензина.** У бензина смесь держится около стехиометрии (14.7:1), и топливо = воздух / 14.7. У дизеля соотношение воздух/топливо меняется от ~18:1 под нагрузкой до 60:1+ на холостых и при сбросе газа. Расчёт по MAF даст ошибку в разы. Нужна цикловая подача или расход, который считает сам ECM.

Кандидаты по порядку:

| # | Источник | Что даёт | Как проверить |
|---|---|---|---|
| 1 | **PID `0x5E`** Engine fuel rate (SAE J1979) | л/ч, `(A×256+B)/20` | бит `0x5E` в маске поддержки PID `0x40` |
| 2 | PID `0x9D` (fuel rate, г/с) / `0xA2` (cylinder fuel rate, мг/ход) | из новых ревизий J1979 | маски `0x80` / `0xA0` |
| 3 | **Широковещательный кадр штатной приборки** | RG показывает мгновенный и средний расход, значит, ECM шлёт расход в BCM/приборку ([HS GMLAN Gateway, duramaxdiesels.com](https://www.duramaxdiesels.com/forum/threads/hs-gmlan-gateway.68389/)). ID и байт для RG неизвестны | SNIFF ANALOG, см. ниже |
| 4 | DID цикловой подачи (мм³/ход) через `$22` | E98 стоит и на Opel 1.6 CDTi, возможно, DID найдётся в их списках | проба DID на `0x7E0` |
| — | ~~MAF + соотношение воздух/топливо~~ | для дизеля непригодно | — |

**GPS для этого** хватает дешёвого ATGM336H (~$3, NMEA, до 10 Гц): одометру нужна скорость, а не 25 Гц. u-blox M10 нужен только для точного замера разгона.

**Первый шаг не требует покупок.** Добавить в прошивку однократное чтение масок поддержки mode 01 (`0x00`, `0x20`, `0x40`, `0x60`, `0x80`, `0xA0`) при старте и вывести их на DIAG. Это только чтение. Одна фотография при ключе на ON и заглушённом моторе скажет, есть ли варианты 1–2.

**Как найти кадр расхода на SNIFF (вариант 3).** Признаки байта расхода:
- **ноль при торможении двигателем** (на передаче, с 2000+ об/мин, газ отпущен — подача отсекается);
- небольшое и ровное значение на прогретом холостом;
- резкий рост при нажатии газа и максимум на полной нагрузке.

Ни один другой сигнал не падает в ноль при сбросе газа на ходу, поэтому найти его должно быть несложно. Масштаб подбирается по варианту 1, если он есть, или по заправкам.

**Формулы:**

```
мгновенный, л/100 км = расход[л/ч] / скорость[км/ч] × 100      (скорость ≥ 5 км/ч)
топливо += расход[л/ч] × Δt / 3600                              (Δt по времени приёма, не больше 2 с)
средний, л/100 км    = топливо[л] / пробег[км] × 100
мм³/ход → л/ч        = Q × (об/мин / 2) × 4 цил × 60 / 10⁶      (вариант 4, 4-тактный, 4 цилиндра)
```

Если источник расхода устарел, топливо не интегрируется, и счётчик помечается «неполный» — как `NaN` для метрик. Ноль подставлять нельзя.

**Калибровка по заправкам.** Расход, который отдаёт ECM, может расходиться с реальным на несколько процентов. Поэтому в `cluster_config.h` будет коэффициент `FUEL_CAL`. Порядок: залить до отсечки пистолета, сбросить СЧЁТЧИК A, проехать бак, снова залить до отсечки и сравнить залитые литры с литрами на СЧЁТЧИКЕ A. Два-три бака дают поправку точнее 2 %.

## 4. Хранение

У платы нет батарейки, питание пропадает вместе с зажиганием, поэтому сохранять нужно часто.

**Вариант по умолчанию — SPI NOR на плате (бесплатно), см. ниже. FRAM — если не жалко ~$2–3:**

**FRAM MB85RC256V** (32 КБ, I2C, 10¹² циклов записи, 2.7–5.5 В; на LCSC [C47538](https://fat.lcsc.com/product-detail/FRAM_FUJITSU-MB85RC256VPNF-G-JNERE1_C47538.html), ~$1.7; готовые модули ~$3–10):
- пишется мгновенно и без стирания, износа нет;
- запись раз в секунду в движении и сразу при остановке. При выключении ключа теряется не больше секунды пробега, а обычно ничего: перед выключением машина стоит;
- две копии (A/B), в каждой номер записи и CRC32. При загрузке берётся новая целая копия, поэтому запись, прерванная пропаданием питания, не портит данные;
- что храним: пробег ОБЩИЙ / ПОЕЗДКА / A (метры, `uint32` — хватит на 4 млн км), литры (мл) и время в движении для каждого счётчика, `K`, `FUEL_CAL`, время UTC последней записи (для автосброса ПОЕЗДКИ), версия формата;
- пины: **I2C1, PB8 = SCL, PB9 = SDA** (AF4), подтяжки 4.7 кОм к 3.3 В (на модулях обычно уже стоят). По `Dash.ioc` и [wiring.md](../wiring.md) свободны; проверить, что выведены на гребёнку WeAct.

**Без покупок (основной вариант):** на WeAct уже есть SPI NOR на 8 МБ (SPI1: PB3/PB4/PD7). Журнальная запись: запись по 32 байта с номером и CRC дописывается раз в секунду в движении и при остановке; когда сектор 4 КБ заполнен, следующий стирается заранее. При загрузке берётся последняя целая запись, так что прерванная запись не портит данные. Износ: ~1 сектор на 128 записей, при 2 ч езды в день это меньше 30 стираний в день на 2048 секторов — запас на десятилетия. Прошивки больше, чем с FRAM, зато бесплатно.

## 5. Экран и управление

Новая страница **TRIP**: DRIVE → TRIP → DIAG → SNIFF.

```
┌──────────── TRIP ────────────┐
│ МГНОВЕННЫЙ      9.4 л/100     │
│ ████████░░░░░░░░░░            │
│                               │
│ ПОЕЗДКА   42.7 км    8.9 л/100│
│           3.80 л     0:48     │
│ СЧЁТЧИК A 612 км     9.6 л/100│
│           58.8 л              │
│ ОБЩИЙ     12 480 км  9.8 л/100│
│ GPS ●  K 0.893   ЗАПАС 610 км │
└───────────────────────────────┘
```

**Управление.** Одна кнопка KEY уже занята: короткое нажатие листает страницы, 3 с — режим яркости. Для сброса счётчика нужно отдельное намеренное действие, поэтому рекомендую **поворотный энкодер с кнопкой (EC11)**:
- вращение — страницы (в режиме яркости — яркость);
- короткое нажатие на TRIP — выбрать счётчик;
- удержание 2 с на TRIP — сбросить выбранный счётчик, с кольцом обратного отсчёта на экране;
- удержание на других страницах — режим яркости, как сейчас KEY.

Пины: **PA6 / PA7** — TIM3 в режиме энкодера, кнопка — **PA0** (EXTI). Проверить по гребёнке. KEY на плате остаётся запасной кнопкой.

**Сброс только на месте:** со свежей скоростью больше 3 км/ч сброс не работает, как и вход в SNIFF.

## 6. Прошивка: из чего состоит

| Модуль | Что делает | Тесты на ПК |
|---|---|---|
| `gps_ubx.c` | UART + DMA, разбор NAV-PVT, настройка модуля ([gps-performance-meter.md](gps-performance-meter.md) §4) | разбор кадров |
| `fram.c` | I2C1, чтение и запись блока, ~1.5 мс на 64 байта на 400 кГц | — |
| `odo.c` | Чистая логика: интеграл по источникам, обучение `K`, счётчики, правила сброса, упаковка записи с CRC | да, как `fdcan_obd.c`: потеря фикса, тоннель, обрыв питания посреди записи, переход счётчика времени через 0 |
| `fuel.c` | Источник расхода (PID / кадр / DID), интеграл, средние, `FUEL_CAL`, «неполный» | да |
| `fdcan_obd.c` | Маски поддержки, PID `0x5E` / кадр расхода, кадр `0x3E9` | расширение текущего набора |
| `input.c` | Энкодер (TIM3) + кнопка, жесты | логика жестов |
| `cluster_ui.c` | Страница TRIP | — |

Объём после драйвера GPS — примерно 1–2 недели вечерами. Основное время уйдёт на поиск источника расхода и калибровку на машине.

## 7. Что сделать первым

1. **Прошивка, без железа:** маски поддержки PID на DIAG → одно фото при ключе на ON и заглушённом моторе. Станет ясно, есть ли `0x5E`.
2. **Лог шины в поездке.** SNIFF открывается только в P, а байт расхода видно только на ходу. Поэтому — USB-CAN адаптер (CANable / candleLight, см. [build-hardware.md](build-hardware.md) §6) на тот же OBD-разветвитель, ноутбук у пассажира, SavvyCAN пишет всю шину. Потом смотрим дома: есть ли `0x3E9`, и какой байт падает в ноль при торможении двигателем. Адаптер включать в режиме только приёма (listen-only), чтобы он ничего не слал в шину; проверить, что выбранная прошивка адаптера и программа это умеют.
3. Объём бака и PID `0x2F` — для запаса хода.
